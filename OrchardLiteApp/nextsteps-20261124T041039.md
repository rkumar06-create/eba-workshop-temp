## Code Changes Required

### 1. Remove hard-coded port binding — `Program.cs`

The call `UseUrls("http://0.0.0.0:80")` is hard-coded. Under .NET 10 container images the process runs as a non-root user (default port **8080**), so binding to port 80 will fail without elevated privileges.

**Remove** the `UseUrls(...)` call from code entirely. Add a configurable default in `appsettings.json` instead:

```json
"Urls": "http://0.0.0.0:5000"
```

Then read it in `Program.cs`:
```csharp
// Replace the hard-coded UseUrls call with:
builder.WebHost.UseUrls(builder.Configuration["Urls"] ?? "http://0.0.0.0:5000");
```

This keeps the binding overridable at runtime via environment variable:
```bash
# .NET 10 preferred multi-port variable
ASPNETCORE_HTTP_PORTS=8080

# or classic override
ASPNETCORE_URLS=http://0.0.0.0:8080
```

### 2. Remove credentials from `appsettings.json`

The `OrchardLiteDB` connection string contains a plain-text password. Replace it with a placeholder:

```json
"ConnectionStrings": {
  "OrchardLiteDB": "Server=localhost;Database=orchardlite;Uid=orcharduser;Pwd=;"
}
```

Supply the real value at runtime via an environment variable (which ASP.NET Core's configuration system resolves automatically, taking precedence over `appsettings.json`):
```bash
export ConnectionStrings__OrchardLiteDB="Server=<host>;Database=<db>;Uid=<user>;Pwd=<password>;"
```

For local development, use .NET User Secrets instead of committing any real value:
```bash
dotnet user-secrets set "ConnectionStrings:OrchardLiteDB" "Server=...;Database=...;Uid=...;Pwd=...;"
```

### 3. Remove hard-coded fallback password in `DatabaseInitializer.cs`

Locate the hard-coded fallback password in `DatabaseInitializer.cs` and replace it with a mandatory configuration read that throws clearly if the value is absent:

```csharp
// Before (adjust to match the actual line)
var password = Environment.GetEnvironmentVariable("DB_PASSWORD") ?? "hardcodedPassword";

// After
var password = Environment.GetEnvironmentVariable("DB_PASSWORD")
    ?? throw new InvalidOperationException(
           "DB_PASSWORD environment variable is required and must not be empty.");
```

If `DatabaseInitializer.cs` reads credentials through the `IConfiguration` abstraction rather than directly from environment variables, ensure the configuration key has no hardcoded default fallback and that startup fails fast with a descriptive message when the value is missing.

## Deployment Considerations

- **Port mapping:** If deploying to a container, map the host port to **8080** (the .NET 10 non-root default) rather than 80, unless `ASPNETCORE_HTTP_PORTS` or `ASPNETCORE_URLS` is explicitly set to 80 and the container is granted the necessary privileges.
- **`MySql.Data` 26.10.0** is the Oracle-rebranded Connector/NET. Confirm the target MySQL server version is 8.0 or later. Review Oracle's Connector/NET release notes for any TLS/SSL default changes that may require updates to existing connection string parameters (e.g., `SslMode`, `AllowPublicKeyRetrieval`).
- **Credentials management:** Before deploying to any shared environment, ensure all secrets are supplied exclusively through environment variables, a secrets manager (e.g., Azure Key Vault, AWS Secrets Manager, HashiCorp Vault), or .NET User Secrets for local development. No real credentials should exist in any committed file.

**What deploys:** web, worker and console projects. Class libraries and test projects are not deployed. WinForms and WPF apps can't run in Linux containers, so skip this step for them. A console app that runs once and exits deploys as an ECS task or a Kubernetes Job, not a long-running service.

Give the prompt below to your coding assistant (Kiro, Claude Code, or another MCP client). It uses the AWS Transform MCP server and the **Source Code Containerization** agent (`vmware-containerization-agent`). That agent builds the image, pushes it to Amazon ECR, generates Terraform or Helm, and deploys to **Amazon ECS or EKS**. For EC2, Elastic Beanstalk or Lambda, stop after Publish Images and deploy the ECR image yourself.

### Setup (once)
- Claude Code: `claude mcp add aws-transform -e AWS_PROFILE=<profile> -- uvx awslabs.aws-transform-mcp-server@latest`
- Kiro: add to `~/.kiro/settings/mcp.json`:
  `{"mcpServers":{"aws-transform":{"command":"uvx","args":["awslabs.aws-transform-mcp-server@latest"],"env":{"AWS_PROFILE":"<profile>"}}}}`
- `AWS_PROFILE` is optional. Without it, the assistant signs in with IAM Identity Center, which opens a browser.
